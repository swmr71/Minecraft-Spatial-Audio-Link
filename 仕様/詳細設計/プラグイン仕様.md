## 1. プラグインの内部構造（アーキテクチャ）
プラグインの責務を 3 つのコンポーネントに分離します。
| コンポーネント | 役割 | 処理頻度 |
|---|---|---|
| **Data Collector** | 全プレイヤーの座標、Yaw、ワールド、ラジオチャンネル、スニーク/水中状態を収集（メインスレッド）。 | 5 Ticks (250ms) |
| **Redis Publisher** | 収集したスナップショットを JSON 化し、Jedis のパイプラインで Redis へ非同期送信。 | 5 Ticks (250ms) |
| **Command Executor** | /vc および /radio コマンドの処理、msal-node API との通信。 | 随時（ユーザー操作時） |

## 2. 座標送信ロジックの詳細設計
### 2.1 送信データのフィルタリング
全プレイヤーのデータを無条件に送るのではなく、**「ボイスチャットに接続中（Web ログイン済み）」**のプレイヤーのみに限定するとさらに軽量化できますが、最初はシンプルに「全オンラインプレイヤー」を対象にしています。
### 2.2 スレッドモデル
Bukkit API はメインスレッド専用、Redis 通信はメインスレッド厳禁です。

```java
// メインスレッドで実行 (runTaskTimer)
public void run() {
    List<String[]> entries = new ArrayList<>();
    for (Player player : Bukkit.getOnlinePlayers()) {
        entries.add(new String[]{uuid, toJson(player)});   // Bukkit API はここで完結
    }
    Bukkit.getScheduler().runTaskAsynchronously(plugin, () -> publish(entries));
}

// 非同期スレッドで実行
private void publish(List<String[]> entries) {
    try (Jedis jedis = jedisPool.getResource()) {
        Pipeline pipeline = jedis.pipelined();
        for (String[] e : entries) pipeline.setex("vchat:player:" + e[0], 5, e[1]); // TTL 5秒
        pipeline.sync();
    }
}
```
JSON スキーマは「Redis・API設計.md」を参照。座標は小数点以下 2 桁に丸め、Yaw は 0〜360 に正規化する。

## 3. コマンド仕様（Command API）
ユーザーがゲーム内から Web へスムーズに遷移するためのインターフェースです。
### /vc join (または /vc link)　— 権限 `msal.use`（既定: 全員）
 1. **内部処理:** msal-node の `/api/vc/token/generate/` へプレイヤーの UUID と名前を送信（`X-MSAL-Key` ヘッダ付き）。
 2. **レスポンス:** 6 桁のワンタイムコード（有効期限 5 分）を受け取る。
 3. **表示:** プレイヤーにクリック可能なメッセージを表示。
   * 「[VC接続] ここをクリックしてログイン（コード: 123456 / 5分間有効）」
   * URL 例: `https://vc.clusters-prj.com/login/?mc_name=Steve`（MCID は自動入力。コードは URL に含めない）
 4. **失敗時:** プレイヤーには汎用メッセージのみ表示し、詳細（接続先・例外内容）はコンソールログにだけ出す。
### /radio <channel>　— 権限 `msal.use`（既定: 全員）
 1. **内部処理:** プレイヤーのメタデータ radio_channel を更新（0〜`radio.max-channel`、既定 999。0 で解除）。
 2. **即時反映:** 次の Redis 送信パケットにこのチャンネル ID が含まれる。
 3. **演出:** チャンネル切り替え時に「カチッ」というサウンド（BLOCK_NOTE_BLOCK_IRON_XYLOPHONE）を再生。
 4. **状態の寿命:** メモリ上のみ。ログアウトでリセットされる。
### /vc broadcast <message...> / /vc broadcast stop (Moderator 以上)　— 権限 `msal.broadcast`（既定: op）
 1. **内部処理:** サーバー全体にタイトルメッセージを表示し、msal-node に放送開始を通知（`/api/vc/plugin/broadcast/start`）。コマンド実行者の声が VC 接続中の全員に届く（距離・方向・ノイズなし。他の音声はダッキング）。
 2. **終了:** `/vc broadcast stop`（コンソールからは全放送停止）。忘れても `BROADCAST_MAX_SECONDS` で自動終了。メッセージとして「stop」だけを送ることはできない。
 3. コンソールからはタイトル表示のみ（声がないため音声放送は不可）。
### /vc mute <channel> / /vc unmute <channel> (担当 Moderator)
 1. **権限:** `msal.mute.*`（全チャンネル）または `msal.mute.<channel>`（担当チャンネルのみ）。LuckPerms のグループにノードを付与して連動させる。
 2. **効果:** ミュート中チャンネルの発話者はラジオでは聞こえなくなる（近接では聞こえる）。Web の管理パネルからも操作可能（Super Admin）。

## 4. 特殊仕様のフラグ管理（ロマン枠）
2km のラジオやノイズ計算を豊かにするために、プラグインから追加で送るステータスです。
 * **is_sneaking:** スニーク中は声が小さくなる（音量 60%）。クライアントで実装済み。
 * **is_in_water:** 水中にいるときは「ボコボコ」としたフィルター（ローパス 700Hz + 7Hz の振幅変調）。実装済み。
 * **y_coordinate:** `p[1]` が 0 以下（地下深く）の話者の近接音声に残響を加える。実装済み。

## 5. 依存ライブラリと設定
ビルドは **Maven**（`pom.xml`）。
 1. **Jedis:** Redis 操作用（パイプライン処理に強い）。maven-shade-plugin で `com.clustersprj.msal.libs.*` に relocate して同梱。
 2. **Gson:** JSON の構築・パース用。**Paper 同梱のため `provided`**（shade しない）。
 3. **HTTP クライアント:** JDK 標準の `java.net.http.HttpClient`（OkHttp は Kotlin stdlib を巻き込むため不採用）。

### config.yml
| キー | 説明 |
|---|---|
| `redis.*` | Redis 接続情報（`timeout-ms` で接続・応答のタイムアウト。Redis が遠いときの送信はスキップして詰まらせない） |
| `backend.base-url` | msal-node のベース URL（内部 IP 例: `http://10.2.1.5:8010`） |
| `backend.login-url` | プレイヤーに案内するログイン URL |
| `backend.api-key` | msal-node の `PLUGIN_API_KEY` と同じ値。**未設定だとプラグインは起動しない** |
| `broadcast.interval-ticks` / `ttl-seconds` | 送信間隔 / キー TTL |
| `radio.max-channel` | `/radio` の最大チャンネル番号 |
